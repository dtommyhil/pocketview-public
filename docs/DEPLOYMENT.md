# Host the read-only portfolio demo

The public demo keeps **Flask and PostgreSQL**, uses **56 fictional transactions**
across two sample accounts, and lets visitors explore the chart and transaction
table. It does not use Plaid credentials or contact Plaid. The full Sandbox
connection, encrypted-token storage, sync and recovery implementation remains
available in the default local mode.

This repository is a public snapshot of the app. The existing live demo deploys
from the separate private development repository; publishing this snapshot does
not change that service. The Blueprint here can be used for a separate deployment.

## Deployment settings

Use **Render Free** for Flask and **Neon Free** for PostgreSQL. The tracked
`render.yaml` declares a free service; do not choose a paid instance or add-ons.
The service waits for GitHub checks to pass before automatic redeployment.

| Setting | Value or source |
| --- | --- |
| GitHub repository | `dtommyhil/pocketview-public`, branch `main` (for a new deployment) |
| Build command | `pip install -r requirements.txt` |
| Start command | `sh scripts/start_demo.sh` |
| Health-check path | `/healthz` |
| `APP_MODE` | `demo` |
| `PLAID_ENV` | `sandbox` |
| `DATABASE_URL` | Dedicated Neon database's **direct** connection URI, with SSL; set privately in Render. |
| `FLASK_SECRET_KEY` | Generated by Render's Blueprint, not copied from the local app. |
| Public hostname | Render supplies `RENDER_EXTERNAL_HOSTNAME`; custom hosting can set an exact `PUBLIC_HOSTNAME`. |

Leave Plaid keys and `TOKEN_ENCRYPTION_KEY` out of this deployment. Demo mode
clears those settings and never initializes the Plaid client or token cipher.
The session key is still a normal server secret; don't put it in code or chat.

## With connected hosting tools

1. Connect Render and Neon using the accounts associated with the project.
2. Create or select a dedicated free Neon project for Pocketview.
3. Transfer its direct SSL connection URI into the Render service's runtime
   environment without printing it or committing it.
4. Deploy the reviewed `main` commit using the settings above.
5. Wait for the deployment to become healthy, then verify the live URL using the
   checklist below. Only a successful deployment produces a hosted-demo link.

## Through the dashboards

If you prefer to configure the services yourself:

1. In [Neon](https://console.neon.tech), create a free project named Pocketview Demo.
   Choose a region near the Render service (the Blueprint uses Oregon).
2. Open the project's connection dialog. Choose a **direct/unpooled** PostgreSQL
   connection and retain its SSL settings. Keep the URI private.
3. In [Render](https://dashboard.render.com), create a Blueprint from the `dtommyhil/pocketview-public` repository. Authorize GitHub access if asked.
4. Use the repository's `render.yaml`. Enter the Neon URI as `DATABASE_URL` in
   Render's setup field. Render generates `FLASK_SECRET_KEY` automatically.
5. Confirm **Free**, `APP_MODE=demo`, the build/start commands and health path.
   Deploy and wait for a healthy result. Do not add your local Plaid credentials.

Neon's pooled connections do not support session-level advisory locks; direct
connections also suit migrations. Pocketview's full local sync implementation
uses an Item session lock, so the deployment documents one compatible connection
type. [Neon connection guidance](https://neon.com/docs/connect/connection-pooling)

The free Render service sleeps after inactivity and may take about a minute to
wake. This is suitable for a small portfolio demo; preview it before an interview.
No keep-alive loop is included. [Render free-service limits](https://render.com/docs/free)

## What startup does

`scripts/start_demo.sh` refuses any mode except `demo`. It applies existing SQL
migrations, seeds the fictional dataset, then starts Gunicorn with one process
and four threads on the provider's `PORT`.

Seeding only replaces the fixed sample Item and its records, in one transaction.
Its owner reference is reserved for public fixtures; local integration mode cannot
use it. Other owners' data is untouched. The sample dates cover the current four
months, and money uses Decimal/numeric. Repeated starts preserve the fixture count.

Public requests can read the dashboard/static assets and filter results. Every
`/api/` request and every mutating HTTP method is rejected before any route can
exchange tokens, sync, reconnect or disconnect. The page loads no Plaid SDK or
bank-action JavaScript. There is no application login because visitors share only
fictional read-only records.

Local integration mode remains restricted to loopback requests. Public demo mode
requires the exact hosting hostname; arbitrary hosts are rejected. Public database
errors show a brief unavailable message, with no local setup instructions/secrets.
